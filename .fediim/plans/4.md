## Alternatives considered
A1 One `webMain` source set for js+wasmJs — js gets DOM types from its stdlib (`kotlinx.browser`, `org.w3c.dom`, `dynamic`) while wasm has neither `dynamic` nor stdlib DOM and needs `JsAny`-typed `js()` externals, so shared web code would have to be written in the wasm interop style and lose js's typed DOM; a direct `kotlinx-browser` dependency is not approved; shared logic already lives in commonMain parsers.
A2 Server hook puts the session token itself in the redirect URL — a long-lived bearer would land in browser history, logs and custom-scheme dispatch; an OTT is single-use and expires in 3 minutes (`one-time-token/index.mjs:22,80`).
A3 `oauthPopup` everywhere with the JVM loopback serving an opener page — Custom Tabs and ASWebAuthenticationSession have no opener, so native needs a second mechanism anyway, and it departs from C6's JVM wording.
A4 `@better-auth/expo` server plugin for native — not installed so unverified for 1.7.17, Expo-oriented, adds an npm dependency (operator declined, L1).
