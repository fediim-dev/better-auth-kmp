## Alternatives considered
- Gate `mavenLocal()` behind an opt-in `fds.local` property — rejected: no current need (1.0.0 is served remotely); FDS developers can add `mavenLocal()` locally when testing an unreleased FDS, and an opt-in path is one more unchecked resolution route into a released build.
- Add `gradle/verification-metadata.xml` for `dev.fediim.fds` — rejected (issue marks it optional): Gradle turns on verification for every dependency once the file exists, so FDS-only entries would fail all other artifacts; full metadata is a separate repo-wide decision.
- Keep `mavenLocal()` but move it after GitHub Packages — rejected: a local artifact still wins for any version GitHub Packages lacks, which is the unverified path the security review flagged.
