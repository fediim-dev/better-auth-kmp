## Alternatives considered
A1 Gradle `startContractServer`/`stopContractServer` with `finalizedBy` — port and pid must cross task boundaries at execution time (pid file plus a late system property), which fights the configuration cache, and a killed daemon/worker skips the finalizer, leaving orphans.
A2 Shared Gradle `BuildService` owning the process — clean lifecycle but needs build-logic code plus a `CommandLineArgumentProvider` to pass the port into the test JVM for one module, and still leaks on a daemon kill without the stdin guard.
A3 Harness runs `npm ci` on every start — not incremental, a network call per test run, and failures surface inside a test instead of as a clear Gradle task error.
