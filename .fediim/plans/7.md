## Alternatives considered
A1 androidx `lifecycle-viewmodel` with `viewModelScope` — not an approved dependency (human-gated, C3); an injected scope plus `close()` gives the same lifecycle on all five targets.
A2 `@Composable rememberAuthState()` state holders — needs the Compose compiler Gradle plugin (a new gated build artifact) and a composition to test on every target; StateFlow plus the app's own `collectAsState()` covers it.
A3 Revoke the old token after the new sign-in — `revoke-session` with the new Bearer deletes only same-user sessions and still answers `{status:true}` (`tests/contract-server/node_modules/better-auth/dist/api/routes/session.mjs:406,415`), so the old session would silently survive. A correct post-sign-in revoke needs a core call that sends `/sign-out` with an explicit old Bearer and no capture, and it still leaves two problems pre-signOut avoids: a mixed-user window (the new token is stored and used while the old user's cache is not yet cleared) and a leaked old session if the app dies between sign-in and revoke. Its only gain is that a failed or same-user re-login keeps the old session, which L4 accepts losing.
A4 Call `onClearUserCache` before an unchanged `signOut()` — the token stays stored while caches are cleared, so app requests during the callback can refill them with the old user's data, and the spec wants storage cleared "immediately" before the revoke.
A5 Inject `AuthTokenStorage` so the VM signs out only when a token exists — a second handle that must match the client's internal one (`BetterAuthClient.kt:74`); `signOut` without a token already sends nothing (`:156`).
