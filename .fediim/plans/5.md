## Alternatives considered
A1 Separate optional `ActiveOrganizationStorage` interface found by an `is` check — atomic clear needs the same instance and mutex as the token anyway, so it adds a second public type and a silent runtime downgrade with no gain (operator chose I1).
A2 No cache; read `session.activeOrganizationId` from `getSession()` each time — authoritative, but violates the locked spec decision that `AuthTokenStorage` persists and clears it.
A3 Endpoints as methods on `BetterAuthClient` — 15 methods push the ~246-line file well past ~300, and the spec names the accessors.
A4 `ApiKeyRecord.key: String?` filled only on create — puts the secret in the type apps list, cache and log; a separate redacted `CreatedApiKey` confines it.
